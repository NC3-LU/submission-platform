# v3.0.0 — draft for review

This release upgrades the platform to Laravel 13 and adds the integration endpoints requested in #49 and #57–#65. It is **not published**. Final verification and branch/deployment checks are recorded below for release review.

## Compatibility and deployment

- PHP 8.3+ and the cURL extension are required. The application uses Laravel 13, Livewire 3.8, PHPUnit 12 and Vite 8. CI/container builds use Node 24. Deploy with the documented migration, backup and rollback workflow.
- File answers in API responses now contain safe metadata and an authorized download URL instead of a storage path. Update integration parsers before rollout.
- API tokens must declare explicit abilities. New abilities are `forms:share`, `submissions:export` and `webhooks:manage`; they do not grant additional account privileges. Legacy `/api/user` Sanctum credentials are distinct from application API v1 tokens.
- `/api/user` and singular `/api/v1/form/{form}/access-links` routes remain available with deprecation headers until 1 April 2027. New clients use `/api/v1/me` and plural `/forms/{form}/access-links`.
- Forms with responses have locked question structures. Duplicate them for a revised questionnaire; drafts remain private to their authors, and final responses cannot be reopened for answer editing.
- Run the queue worker and scheduler. `INTEGRATION_QUEUE_CONNECTION` defaults to `database` and must be asynchronous. Export files expire after 24 hours; webhook delivery history expires after seven days. Integration/token audit metadata has no automatic expiry.
- Webhooks remain disabled by default. Enabling them requires a reviewed receiver URL, receiver-side signature verification and deduplication, and appropriate outbound DNS/HTTPS access.
- Production deployments remain manual on the server. A future application/database move to Dokploy has a separate [migration plan](../plans/dokploy-migration.md).
- The default branch is now `main` following #47. Deployment targets and existing clones must follow the new name; see [operations](../operations.md).
- The release preserves the tested Tailwind 3 toolchain. A Tailwind 4 manifest update on the former default branch lacked the PostCSS migration and failed an isolated build; that incomplete dependency change is excluded.

## Changes

- Corrected submission validation, conditional answers, availability windows, draft privacy, replay protection, private-file ownership and cleanup after transactions.
- Improved keyboard/focus behavior, accessible form controls, mobile layouts, error feedback and builder safeguards. Revealed fields remain fully visible when validation moves keyboard focus.
- Added safe API token context, self-revocation, scoped lifecycle history and atomic bounded batch revocation (#57, #58, #60).
- Added authorized API attachment downloads and shared web/API malware gating; file paths are no longer exposed (#59).
- Added full Pandora worker verdict details for authorized submission viewers, with escaped output, secret removal and unchanged warning/blocking behavior (#49).
- Added independent transactional API/web form duplication, including header copies and remapped conditional fields (#61).
- Added owner/administrator-controlled collaborator management with explicit abilities, scoped membership and audit records (#62).
- Added bounded queued JSON/XLSX exports with private artifacts, current authorization checks, expiry, cleanup and formula-safe strings (#63).
- Added opt-in signed webhook management, rotation, delivery history, testing and redelivery; DNS validation/socket pinning, no redirects/proxies, bounded response handling/retries and minimal event payloads (#64).
- Established canonical plural access-link routes while retaining migration aliases (#65).
- Added dependency auditing, SQLite/MySQL tests, browser/accessibility checks and both runtime image builds in CI; hardened health checks, queue/scheduler monitoring, encrypted backup, restore drills and rollback tooling.
- Documented account/form ownership transfer, API contracts and operations procedures.

OpenAPI exports without warnings (29 paths, 48 unique operations, bearer authentication). Container checks confirm built assets and required extensions, with no bundled `.env` or runtime upload files. GitHub CI passed on [dev](https://github.com/NC3-LU/submission-platform/actions/runs/34848690034) and [main](https://github.com/NC3-LU/submission-platform/actions/runs/34849007437) for implementation commit `176e97c`.
